# Планирование отпусков сотрудников

Веб-приложение для подачи и согласования отпусков: графический выбор периода,
недоступные периоды (учёба и т.п.), контроль загруженности отделов, оргструктура
из внешней системы, управляемые ограничения и льготы. Полное описание архитектуры
и поэтапный план — [план проекта](План_проекта_GrafikHolyday.md).

Стек: FastAPI + PostgreSQL (бэкенд), React + TypeScript (фронтенд). Реализованы Kerberos/SPNEGO через AD-домен и dev-вход для локальной разработки. На стенде `https://192.168.0.10/` включён Kerberos challenge, dev-вход недоступен (проверено 24.09.2026). Успешный доменный вход этой проверкой не подтверждался.

## Быстрый старт (локальная разработка)

### Бэкенд

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"

docker compose up -d db
.venv/bin/alembic upgrade head
.venv/bin/python -m scripts.seed_dev_data

.venv/bin/uvicorn app.main:app --reload
```

API-документация: http://localhost:8000/docs

### Фронтенд

```bash
cd frontend
npm install
npm run dev
```

Приложение: http://localhost:5173 — в dev-режиме предлагает выбрать тестового
пользователя вместо реального SSO (см. `AUTH_PROVIDER=dev` в `backend/app/config.py`).

### Тесты

```bash
cd backend
.venv/bin/pytest
```

### Windows / PowerShell

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
docker compose up -d db
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m scripts.seed_dev_data
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

В другом терминале: `cd frontend`, затем `npm.cmd ci` и `npm.cmd run dev`.
Тесты из `backend`: `.\.venv\Scripts\python.exe -m pytest -q`.
Для изолированных проверок без фоновых синхронизаций перед запуском сервера
задайте `$env:ENABLE_SYNC_SCHEDULER="false"`. Dev-данные предназначены для локальной БД.

## Доступ с других компьютеров сети

По умолчанию всё слушает только localhost. Для доступа с другого компьютера:

1. **Бэкенд** — запускать с `--host 0.0.0.0`:
   ```bash
   .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
2. **Фронтенд (dev-режим)** — уже настроен слушать все интерфейсы
   (`server.host: true` в `vite.config.ts`), просто `npm run dev`.
3. **CORS** — бэкенд должен явно разрешить источник, с которого открывают
   фронтенд. В `backend/.env`:
   ```
   CORS_ORIGINS=["http://<IP-или-домен-сервера>:5173"]
   ```
4. **Файрвол** — на Windows разрешить входящие подключения на портах 5173 и
   8000 (Панель управления → Брандмауэр Windows → Разрешить приложение,
   либо `netsh advfirewall firewall add rule ...`).

Дальше открывать `http://<IP-сервера>:5173` с любого компьютера в той же сети.

### Для боевого (продуктив) окружения

Dev-сервер (`npm run dev`) не предназначен для постоянной эксплуатации.
Рекомендуемая схема:

- Собрать фронтенд статикой: `npm run build` (результат в `frontend/dist`).
- Отдавать `dist/` через nginx (или любой веб-сервер) с проксированием
  `/api/*` на бэкенд — тогда фронт и бэк на одном origin, CORS не нужен.
- Бэкенд — `uvicorn`/`gunicorn` за тем же nginx, не напрямую наружу.
- TLS-сертификат на nginx (Let's Encrypt или корпоративный CA).
- Реальные значения `CORS_ORIGINS`, `DATABASE_URL` — через переменные
  окружения/`.env`, не хардкодить.
- Настройки внешних источников — во вкладке «Интеграции» (см. ниже); реальный
  вход через Kerberos/SPNEGO (`AUTH_PROVIDER=kerberos`) требует настройки
  keytab и hostname конкретного сервера; режимы описаны в инструкции развёртывания.

### Установка в закрытом контуре без интернета (РЕД ОС 8)

Готовый набор скриптов и конфигов — в [`deploy/redos8/`](deploy/redos8/README.md):
сборка офлайн-бандла (wheel-пакеты + собранный фронтенд + portable Python 3.11)
на машине с интернетом, перенос одним архивом, установка на РЕД ОС 8 без
доступа к интернету (`nginx` + systemd-юнит бэкенда).

## Текущее состояние (24.09.2026)

Сверка со стендом: [отчёт и контрольные суммы](docs/deployment-comparison-2026-09-24.md).
Свежая сборка фронтенда побайтно совпала с JS/CSS сервера; OpenAPI
совпадает полностью (47 путей). Внутренние файлы серверного бэкенда
по HTTP не проверялись. Локально: **251 тест проходит**, сборка TypeScript/Vite успешна.

Реализовано:

- Заявки с сохраняемыми черновиками периодов и групповой отправкой,
  согласованием и отменой; администрирование заявок и журнал изменений.
- Календарь на плановый год, недоступные периоды, баланс дней и нагрузка
  подразделений. Дни отпуска считаются календарными за вычетом праздников
  из `backend/app/core/holidays.py` (включая 31 декабря по требованиям проекта).
- Оргструктура и сотрудники: CRUD, импорт, синхронизация, сохранение
  ручной деактивации; назначение согласующих и делегирование.
- Выплата ЕСВ: порог длительности и отдельные ограничения по стажу для
  новичков и сотрудников со стажем от года; даты приёма и увольнения из источника.
- Три независимые интеграции: оргструктура/сотрудники, учебные планы,
  дни отпуска/льготы; тестовое подключение к источнику учебных планов.
- Автосинхронизация: `app/scheduler.py`, APScheduler, проверка каждые 60 секунд.
  Источник запускается при включённой настройке и `poll_interval_minutes > 0`.
  `ENABLE_SYNC_SCHEDULER=false` отключает фоновые запуски; по умолчанию они включены.
- Kerberos в режимах nginx/python и аварийный вход HR-admin.
- Боковая навигация, светлая/тёмная тема с сохранением выбора.
- Офлайн-развёртывание на РЕД ОС 8; сохранение серверного `.env` при обновлении.

В бэклоге: Playwright smoke-тест в репозитории, решение об использовании
категории сотрудника `kat`, уточнение сценариев из раздела «Открыто после 6.37»
в плане проекта. Исторические проверки в плане относятся к указанным там этапам.

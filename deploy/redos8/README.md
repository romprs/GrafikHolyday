# Офлайн-развёртывание на РЕД ОС 8 (закрытый контур)

Ни `pip install`, ни `npm install` без интернета не работают — оба тянут
пакеты с внешних реестров. Схема ниже: один раз собрать всё необходимое на
машине с интернетом (ваш текущий Windows-компьютер), перенести один архив
на закрытый контур и установить там без какого-либо сетевого доступа наружу.

На РЭД ОС 8 не нужен ни Node.js, ни доступ к dnf-репозиториям с интернетом —
только уже установленный `nginx` (из локального репозитория/установочного
диска РЕД ОС) и работающий сервер PostgreSQL, к которому есть доступ по сети.

Python 3.11 не берётся из репозиториев РЕД ОС (в базовой поставке РЕД ОС 8
обычно не гарантирован пакет именно 3.11) — вместо этого в бандл
зашивается самодостаточная сборка CPython 3.11
([python-build-standalone](https://github.com/astral-sh/python-build-standalone)),
которая просто распаковывается в `/opt` и ничего не устанавливает в систему.

## Шаг 1. На машине с интернетом (Windows)

1. Откройте страницу релизов
   https://github.com/astral-sh/python-build-standalone/releases и найдите
   самый свежий файл вида

   ```
   cpython-3.11.<x>+<дата>-x86_64-unknown-linux-gnu-install_only.tar.gz
   ```

   (обычная сборка — без `-debug`, `-noopt`, `freethreaded` в имени).
   Скопируйте прямую ссылку на файл.

2. Из корня репозитория запустите:

   ```powershell
   powershell -ExecutionPolicy Bypass -File deploy\redos8\build-bundle.ps1 -PythonStandaloneUrl "<ссылка из п.1>"
   ```

   Скрипт:
   - скачивает portable Python;
   - скачивает все Python-зависимости бэкенда в виде готовых `.whl`
     (`pip download --platform manylinux_2_28_x86_64 ... --only-binary=:all:`
     — без компиляции на этапе установки на РЕД ОС);
   - собирает фронтенд (`npm run build`) в статику;
   - копирует исходники бэкенда и конфиги установки;
   - упаковывает всё в
     `deploy\redos8\dist\vacation-planner-offline-bundle-<дата>.tar.gz`.

   Требования на этой машине: Python 3.11 (тот же, что уже используется для
   `backend\.venv`), Node.js/npm, `tar.exe` (встроен в Windows 10/11).

   Если дев-машина не Windows, а Linux/macOS/WSL — используйте
   `deploy/redos8/build-bundle.sh <URL>` (тот же результат).

## Шаг 2. Перенос

Скопируйте получившийся `.tar.gz` на закрытый контур (флешка/другой
согласованный канал). Один файл — там уже всё нужное для установки.

## Шаг 3. На РЕД ОС 8

Предварительно должны быть доступны (уже есть на закрытом контуре, отдельно
от этого бандла):
- пакет `nginx` (установить из локального репозитория: `dnf install nginx`,
  если ещё не установлен);
- работающий PostgreSQL и данные для подключения к нему.

Установка:

```bash
mkdir vacation-bundle
tar xzf vacation-planner-offline-bundle-<дата>.tar.gz -C vacation-bundle
cd vacation-bundle
sudo ./install.sh
```

`install.sh` идемпотентен — его можно перезапускать (например, после того
как отдельно доустановили `nginx`). Он:

1. распаковывает portable Python в `/opt/vacation-planner/python`;
2. копирует исходники бэкенда и статику фронтенда;
3. создаёт venv и ставит зависимости офлайн (`pip install --no-index
   --find-links=wheelhouse ...`);
4. создаёт `backend/.env` из шаблона, если его ещё нет (**не
   перезаписывает** при повторном запуске);
5. накатывает миграции Alembic;
6. ставит и запускает systemd-юнит `vacation-backend` (uvicorn на
   `127.0.0.1:8000`, от отдельного системного пользователя `vacation`);
7. настраивает nginx (раздача `frontend-dist` + проксирование `/api/*` на
   бэкенд — та же схема, что и dev-прокси в `vite.config.ts`), включая
   типовые поправки SELinux (`httpd_can_network_connect`,
   `restorecon` на каталог статики) и открытие портов 80/443 в firewalld,
   если он активен.

### После установки — обязательно

Отредактируйте `/opt/vacation-planner/app/backend/.env`:

- `DATABASE_URL` — реальная строка подключения к PostgreSQL;
- `CORS_ORIGINS` — реальный адрес, с которого открывают приложение (при
  этой схеме — тот же origin, что и nginx, поэтому CORS фактически не
  используется, но пусть будет корректным);
- `AUTH_PROVIDER` — по умолчанию `dev` (вход под тестовым пользователем,
  без реального SSO). Для боевой эксплуатации нужен `oidc` — это отдельная
  задача, ещё не подключённая на бэкенде (см. открытые допущения в плане
  реализации). Оставлять `dev` в проде — осознанный временный шаг, не
  забудьте про него.

После правки `.env`:

```bash
sudo systemctl restart vacation-backend
```

### Проверка

```bash
curl http://127.0.0.1:8000/health        # бэкенд напрямую
curl http://<адрес-сервера>/health       # через nginx
```

Приложение — `http://<адрес-сервера>/` в браузере.

### Обновление версии в будущем

Повторите шаг 1 на машине с интернетом (после изменений в коде), перенесите
новый архив, распакуйте и запустите `install.sh` заново — он безопасно
обновит код, зависимости и статику поверх текущей установки и применит
новые миграции. Существующий `.env` не будет тронут.

## Файлы в этой папке

| Файл | Назначение |
|---|---|
| `build-bundle.ps1` / `build-bundle.sh` | Собрать офлайн-бандл на машине с интернетом |
| `install.sh` | Установка/обновление на РЕД ОС 8 |
| `nginx-vacation.conf` | Шаблон конфига nginx (статика + прокси `/api`) |
| `vacation-backend.service` | Шаблон systemd-юнита бэкенда |
| `.env.example` | Шаблон `backend/.env` для продуктива |
